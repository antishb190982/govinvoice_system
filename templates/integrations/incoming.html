Mail administrator: secure relay setup

Forward the dedicated mailbox through your trusted mail gateway to {% url 'api:mail_receive' %} using HTTPS and a single-purpose bearer token created under API clients. Bind that client to this mailbox. Restrict its IP addresses and organisational scope where practical. Tokens are shown only when issued; do not put them in e-mails or invoice files.

The trusted relay must verify sender authenticity (including aligned DMARC or equivalent trusted transport evidence), scan attachments, preserve the actual mailbox receipt timestamp and export the complete RFC822 message. Never copy authenticity claims from sender-controlled headers.

POST multipart fields: mailbox, delivery_id (stable relay delivery identifier), received_at (ISO8601 with timezone), authenticated_sender, authentication_passed (true only on success), attachments_clean (true only after scanning), message_sha256, and the original message file as message. Maximum 25 MB per message; invoice upload limits also apply. A repeated delivery ID with identical content is acknowledged without staging twice; conflicting content is rejected.

Unmapped or unauthenticated senders are rejected. Missing clean-scan evidence quarantines the message without reading invoice attachments. Safe messages stage into Upload Utility Records for normal account registration, invoice checks, reconciliation and batch processing. They never automatically approve or pay bills.
